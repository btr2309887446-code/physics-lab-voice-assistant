## 2. 登录后确定项目目录

本指南使用 `devuser` 账号。`~` 和 `$HOME` 表示当前登录者的家目录；以后换账号时它们的值会变化。先确认项目实际位置，再设置下面三个变量，后续命令都使用它们：

```bash
whoami
id

# 项目、服务端工程和日志目录均已在本次目录清单中确认存在
PROJECT_ROOT="/home/devuser/xiaozhi"
SOURCE_ROOT="$PROJECT_ROOT/server-src"
LOG_ROOT="$PROJECT_ROOT/logs"

ls -ld "$PROJECT_ROOT" "$SOURCE_ROOT" "$LOG_ROOT"
ls "$SOURCE_ROOT/main"
```

如果项目迁到共享目录，第一行变量也要改成共享目录中的实际路径；服务器源码目录名称若不再是 `server-src`，相应修改 `SOURCE_ROOT`。出现“目录不存在”或“没有权限”时，先向负责人确认路径与账号权限。

| 路径（相对项目根目录） | 用途 |
| --- | --- |
| `server-src/main/xiaozhi-server/` | Python 核心服务：语音接收、识别、检索、LLM 与 TTS |
| `server-src/main/manager-api/` | Java 管理 API：智能体、设备、模型与知识库管理 |
| `server-src/main/manager-web/` | Web 智控台 |
| `logs/` | 服务日志 |
| `start-all.sh`、`stop-all.sh` | 已确认文件存在的启停脚本，执行前确认当前内容适用 |
| `server-src/main/xiaozhi-server/data/.config.yaml` | 核心服务私有运行配置 |
| `server-src/main/manager-api/src/main/resources/application-dev.yml` | 管理后端的环境配置 |
| `ollama-data/models/` | 已确认存在的模型目录；实际运行路径由配置确认 |

上表中的源码目录、日志目录和启停脚本已在检查清单中确认存在；私有配置文件及其内容尚未取得，本次没有确认进程正在使用哪份代码。RAGFlow 为独立部署，其根目录已确认是 `/home/devuser/ragflow`；原文、切片和索引保存在实际配置的数据存储中，不能只凭目录存在判断知识库内容或容器状态。

## 3. 查看服务状态

| 服务 | 历史端口 | 作用 |
| --- | --- | --- |
| xiaozhi-server | 8000 | 设备与应用端的 WebSocket 会话 |
| manager-web | 8001 | 智控台网页 |
| manager-api | 8002 | 智控台后端 |
| MySQL / Redis | 3306 / 6379 | 小智管理数据与缓存 |
| RAGFlow | 8880 | 知识库网页入口 |
| Ollama | 11434 | 本地 LLM 与 Embedding |

查看端口监听和 GPU 使用情况：

```bash
ss -ltn | grep -E ':(3306|6379|8000|8001|8002|8880|11434)[[:space:]]'
nvidia-smi
```

端口监听只能说明有服务接收连接，不能单独证明 ASR、检索和回答都正常；还要看对应日志与实际请求。

查看智控台 HTTP 返回及本地模型服务：

```bash
curl --max-time 5 -s -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:8001/

# 使用当前服务器确认的 Ollama 可执行文件位置
"$PROJECT_ROOT/bin/ollama" ps
"$PROJECT_ROOT/bin/ollama" list
```

`ps` 查看当前加载的模型，`list` 查看已保存的模型。若账号具有容器查看权限，可查看 RAGFlow 等容器的状态：

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```

## 4. 查看日志

```bash
# 查看最近日志
tail -n 60 "$LOG_ROOT/server.log"
tail -n 60 "$LOG_ROOT/manager-api.log"
tail -n 60 "$LOG_ROOT/manager-web.log"

# 持续查看核心服务新增日志
tail -f "$LOG_ROOT/server.log"
```

按 `Ctrl+C` 结束日志查看，不会因此停止服务。日志名称或位置与上述不同，以实际启动配置为准。

需要定位错误时：

```bash
grep -Ei 'error|exception|fail' "$LOG_ROOT/server.log" | tail -n 20
grep -Ei 'error|exception|fail' "$LOG_ROOT/manager-api.log" | tail -n 20
```

反馈问题时记录时间、操作和错误现象，再提供相应日志片段，隐去其中的令牌和私有信息。

## 6. 查看 Git 与更新代码

10-11第5步对 `/home/devuser/xiaozhi/server-src` 的检查返回 `not a git repository`，所以该工程目前没有可用的提交编号。负责人仍在核对源码与保存范围；下面的查询适用于后续已有 Git 的源码目录：

```bash
if git -C "$SOURCE_ROOT" rev-parse --show-toplevel; then
  git -C "$SOURCE_ROOT" branch --show-current
  git -C "$SOURCE_ROOT" rev-parse HEAD
  git -C "$SOURCE_ROOT" log -10 --date=short --format='%h %ad %s'
  git --no-optional-locks -C "$SOURCE_ROOT" status --short --untracked-files=all
  git -C "$SOURCE_ROOT" diff --stat HEAD
else
  printf '当前目录未识别 Git 仓库，由负责人安排源码核对和版本保存。\n'
fi
```

交接包提供源码文件，不包含 `.git` 提交历史。若服务器目录由交接包解压上传而来，以上命令可能返回 `not a git repository`；此时由负责人提供已确认的 Git 仓库副本或克隆方式，再在独立工作区使用分支与提交。现有运行目录是否保留 Git 仓库，以这些只读检查的结果为准。

`M` 表示修改，`??` 表示未跟踪文件。只有提交编号一致还不能说明实际文件一致，也要看未提交内容。交接源码中的凭证已清空，因此正式环境配置应保留线上实际值。

代码更新流程：先取得服务器当前对应文件，与本地副本比对；在自己的工作目录修改并提交，由负责人确认合并范围；保存线上原文件与配置后，再更新正式服务。每位同学使用独立工作区，在各自分支中修改；同一目录内切换分支会影响该目录的其他使用者。

| 修改位置 | 线上生效需要什么 |
| --- | --- |
| Python 核心源码 | 使用正确 Python 环境，重新启动核心服务；依赖变化另行处理 |
| Java 管理后端 | 在正确构建环境重新打包，再重启管理 API |
| Web 智控台 | 根据实际运行方式重新构建或重启前端；依赖变化另行处理 |
| 智控台内的智能体模型或功能配置 | 保存配置后让相应设备重新连接 |
| 已关联知识库的文档 | 上传并解析完成，检查切片及召回结果 |

上传源文件本身不等于 Java、Web 或已加载的 Python 服务已经更新。部署与构建方式由负责当前运行环境的人执行。

## 7. 服务启停

现有部署有 `start-all.sh` 和 `stop-all.sh`。由负责运行服务的账号，在确认脚本仍适用于当前目录和环境后执行：

```bash
# 启动现有小智服务
bash "$PROJECT_ROOT/start-all.sh"

# 停止现有小智服务
bash "$PROJECT_ROOT/stop-all.sh"
```

停止会影响当前使用中的设备和智控台，按负责人安排操作。脚本历史上使用原账号的 `$HOME` 路径；新账号或共享目录不能直接沿用，需先完成路径适配。RAGFlow 与 Ollama 是否由这两个脚本管理，要看当前脚本，不能默认它们也已启动或停止。启停后用第3、4节检查状态与日志。

服务正常以后台方式运行时，退出 SSH 通常不会使其停止。是否后台运行，以实际启动方式为准。

项目已有本地 Ollama、ASR 和 RAGFlow 部署记录，日常使用不需要先假定必须开代理。安装依赖、下载模型或调用某些云接口时，如目标网络不可达，再由负责人安排代理。

